Before you begin

Work through Parts 1–7 in order. The times are a guide and include time to try things and correct mistakes. If an exercise takes longer, use its hint or ask a demonstrator. The optional practice can wait.

For each example: run it, change something, then explain what changed. Keep your scripts and a few notes about their output. By the end, you should be able to:

  • Run and edit a Python script.
  • Use a loop and a condition to select items.
  • Distinguish text from bytes and convert between them.
  • Read a file, request a URL and save a short result.

Need another explanation? Use the linked LearnPython.org lessons when useful. They are optional; you do not need to finish the whole tutorial. Use a local Python editor for the file and URL exercises.

Part 1 · 10 minutes

Run your first script

Create a file, run it, then make a small change.

  1. Download the practice files and extract the ZIP. Open the extracted week1-python folder. It contains a data folder.
  2. Open your Python editor. If you have IDLE (Python 3), choose File → New File. Otherwise use the editor provided in your lab and ask a demonstrator if you are unsure how to run Python.
  3. Type the following into a new file and save it as hello.py inside week1-python. Use a plain text/code editor, not a word processor.
Python · hello.py
print("Hello, security practical!")
print(3 + 4)

In IDLE, choose Run → Run Module (F5). The output appears in its Shell window. A script is a file of instructions; Python runs these instructions from top to bottom.

Expected output
Hello, security practical!
7

print(...) displays a value. It is a function: a named operation. The value inside the parentheses is its input. Quotation marks tell Python that something is text; 3 + 4 asks it to calculate a sum.

Try it

Change the greeting. Add a third line that prints 12 * 5, where * means multiplication. Save and run the file again.

Using a terminal instead of IDLE

Open a terminal in week1-python (your file manager may offer “Open in Terminal”). Run the version command first; it should report Python 3. Then run your script. These are terminal commands, not Python code.

Terminal · Linux / macOS
python3 --version
python3 hello.py
Terminal · Windows
py -3 --version
py -3 hello.py

If your lab uses python instead, check python --version reports Python 3 and use that command throughout. A “command not found” message means the terminal cannot find Python; ask a demonstrator. If you see >>>, you are inside Python: type exit() before running terminal commands.

Checkpoint

Your changed greeting appears, followed by 7 and 60. If the old greeting appears, save the file and check which file you ran.

Part 2 · 15 minutes

Values and text

Store values and use them in a message.

Create values.py in the same folder. A variable is a name you give to a value. The = sign assigns a value to a name.

Python · values.py
name = "Alex"
files_checked = 3
files_remaining = 2

print("Hello", name)
print("Total files:", files_checked + files_remaining)
print("Characters in the name:", len(name))

name holds a string (str), which is text. The two counts are integers (int), which are whole numbers. len(...) gives the length of a value such as a string. Commas let print display several values with spaces between them.

Try it

  1. Before running the script, predict the total. Run it and check.
  2. Change name and both counts, then run it again.
  3. Replace the first line with the line below. Run it and type a name when asked.
Python · replacement first line
name = input("Your first name: ")

input(...) shows a prompt and waits for you to type something and press Enter. The result is text, even if you type digits.

Checkpoint: text or number?

Predict these two outputs, then try them at the end of your script.

Python · add to values.py
print("3" + "2")
print(3 + 2)

The outputs are 32 and 5. With strings, + joins text. With integers, it adds numbers. Use int("3") to convert the text "3" to the number 3. Text such as "three" cannot be converted this way.

Extra help: LearnPython: Variables and Types

Part 3 · 20 minutes

Lists, choices and loops

Repeat an operation and act only on matching values.

Create checks.py. A list holds several values in order. Square brackets surround the list; commas separate its items.

Python · checks.py
statuses = [200, 404, 200, 403]

for status in statuses:
    print("Status:", status)
    if status == 200:
        print("Request succeeded")
    else:
        print("Check this response")

for runs the indented instructions once for each item. On each pass, status takes the next value. if checks a condition; else handles the other case. == compares values. It is different from =, which assigns a value.

These are HTTP status codes: 200 means success, 404 means not found and 403 means forbidden. Here they are just numbers in a list; the script has not contacted a server.

Spaces matter. Use four spaces for each level of indentation. The second print is eight spaces in because it is inside both the loop and the if. A colon introduces each indented block. Most editors add the spaces after you press Enter.

Try it

  1. Run the example. Add 404 to the end of the list and run it again.
  2. Count successful responses: put successes = 0 before the loop. Inside the if block, add successes = successes + 1.
  3. After the loop, add print("Successful:", successes) with no indentation. It should print the total once.
Hint: where does the counter go?

Set the counter to zero once, before for. Put the line that increases it directly below print("Request succeeded"), at the same indentation. Keeping the final print outside the loop gives one total.

Checkpoint

The final total is 2, including after you add another 404. Change one 404 to 200: the total should increase to 3. If the total keeps resetting, check where you set it to zero.

Extra help: Lists, Conditions and Loops on LearnPython.

Part 4 · 25 minutes

Work with bytes

Inspect raw values and see how an encoding connects bytes to text.

Files and network responses contain bytes. A byte is eight bits and can hold a value from 0 to 255. Python’s bytes type holds a sequence of these values. Some byte sequences represent text; others represent images, executable code or other data.

Text → bytes → text

Create byte_work.py and run this example.

Python · byte_work.py
text = "café"
raw = text.encode("utf-8")

print(text)
print(raw)
print("Characters:", len(text))
print("Bytes:", len(raw))
print(raw.decode("utf-8"))

.encode("utf-8") converts text to bytes using UTF-8. .decode("utf-8") interprets those bytes as text. Operations written after a dot, such as text.encode(...), are called methods: they act on the value before the dot.

The word has four characters but uses five UTF-8 bytes: é needs two. The b in Python’s display b'caf\xc3\xa9' marks a bytes value; it is not an extra byte. The \x notation shows a byte value in hexadecimal.

Positions and slices

Add the following to the same file. b"ABC" is a short way to write bytes containing these ASCII characters.

Python · add to byte_work.py
message = b"ABC"
print(message[0])
print(message[:2])
print(message.hex())

for value in message:
    print(value)
Position 0A65 decimal · 41 hex
Position 1B66 decimal · 42 hex
Position 2C67 decimal · 43 hex

Positions start at zero. message[0] gives one byte as an integer: 65. A slice such as message[:2] gives bytes up to, but excluding, position 2: b'AB'. Looping through bytes also gives integers.

Hexadecimal uses the digits 0–9 and a–f. Two hex digits describe one byte. .hex() returns a text representation; it does not change the original bytes.

Try it

  1. Change "café" to "cafe". Predict both lengths, then check.
  2. Print the final byte of message using its position.
  3. Use bytes.fromhex("48 69 21") to make a new bytes value. Print it, then decode it as UTF-8.
Hint

The final position in a three-byte value is 2. For the hex exercise, assign the result to a variable, for example greeting = bytes.fromhex("48 69 21"), then use greeting.decode("utf-8").

Checkpoint

"cafe" has four characters and four UTF-8 bytes. message[2] is 67. The hex bytes decode to Hi!. Explain why message[0] gives a number but message[:1] gives b'A'.

Not every file is text. Decoding arbitrary bytes as UTF-8 can raise UnicodeDecodeError. Keep binary data as bytes. Removing or ignoring undecodable bytes changes the data.

Part 5 · 15 minutes

Read and save files

Apply the same operations to a small file on disk.

Create files.py alongside the data folder. pathlib is a module, a collection of tools included with Python. The import line makes its Path tool available.

Python · files.py
from pathlib import Path

raw = Path("data/sample.bin").read_bytes()
print("Bytes:", len(raw))
print("Hex:", raw.hex())
print("First byte:", raw[0])

Path("sample-copy.bin").write_bytes(raw)

Path("data/sample.bin") identifies a file in the data folder. read_bytes() reads it into memory. write_bytes(raw) saves the bytes to another file. Here the paths are relative to your current working folder; run your scripts from week1-python.

Writing to an existing filename replaces its contents. Use the new output names shown here so the supplied data stays available.

Try it

  1. Run the script. Locate sample-copy.bin in your folder.
  2. Add a loop that prints each byte as an integer. How many values are greater than 127? You can count by looking at the output.
  3. Add the text-file example below and run the script again.
Python · add to files.py
text = Path("data/practice-report.txt").read_text(encoding="utf-8")
lines = text.splitlines()
print("Lines:", len(lines))
print(lines[0])

Path("notes.txt").write_text("I inspected six bytes.\n", encoding="utf-8")

read_text(...) reads and decodes in one step. encoding="utf-8" names an option passed to the method. splitlines() turns the text into a list of lines, removing the line endings. In a string, \n writes a newline.

Checkpoint

The binary file contains 6 bytes. Its hex is 0041427f80ff; its first byte is 0. Two values are greater than 127: 128 and 255. The text file has 5 lines and begins OK backup finished.

FileNotFoundError?

Check that you extracted the ZIP and saved your scripts beside data. To see where Python is looking, add print(Path.cwd()) after the import. In IDLE, save the script in week1-python and run it with F5. In a terminal, open the terminal in that folder. Check the spelling and capitalisation of the path.

Part 6 · 20 minutes

Request a URL

Retrieve the same practice report over HTTP and inspect the response.

A browser requests a URL and displays the response. Python can make a request too. We will use urllib.request, which is included with Python, so you do not need to install a package.

Open the practice report in your browser. Copy its full address from the address bar, including https:// (or http:// for the local fallback).

Practice URL for this copy of the pagedata/practice-report.txt

Create fetch_report.py. Run it and paste the full URL when prompted.

Python · fetch_report.py
from urllib.request import urlopen

url = input("Paste the practice URL: ").strip()

with urlopen(url, timeout=10) as response:
    print("HTTP status:", response.status)
    raw = response.read()

print("Downloaded bytes:", len(raw))
text = raw.decode("utf-8")
print(text)
  • .strip() removes accidental spaces at the start or end of your input.
  • urlopen(...) makes a request. Here it uses HTTP GET to retrieve the resource. timeout=10 sets a timeout for blocking network operations, in seconds.
  • with ... as response: keeps the response open for the indented block, then closes it. Keep both lines inside that block indented.
  • response.read() gives the response body as bytes. This supplied file is UTF-8 text, so we decode it with UTF-8. Other resources may use other encodings or contain binary data.

Try it

  1. Check that the status is 200 and that five report lines appear.
  2. Add print(raw[:10]) after the with block to inspect the first ten downloaded bytes.
  3. Change the filename in your input URL to no-such-report.txt and run the script once. Read the final line of the error. Restore the correct URL afterwards.
Checkpoint

The first ten bytes are b'OK backup '. A missing resource on the practical site should give HTTP Error 404: Not Found. In this case, urlopen raises an error before the indented block runs. A script can stop on an error; it does not necessarily reach the final print.

Working offline, or unable to reach the hosted page?

You can still practise a real HTTP request on your own computer. Open a terminal inside the extracted week1-python folder and run:

Terminal · Linux / macOS
python3 -m http.server 8000 --bind 127.0.0.1
Terminal · Windows
py -3 -m http.server 8000 --bind 127.0.0.1

Leave this terminal running. Use IDLE or a second terminal to run your Python script. Enter http://127.0.0.1:8000/data/practice-report.txt when it asks for the URL. 127.0.0.1 means this computer. Stop the server afterwards with Ctrl+C. If port 8000 is already in use, use 8001 in both the command and URL.

A URL beginning file:// opens a disk file rather than making an HTTP request; use the local server for this part.

Part 7 · 15 minutes

Write a small checker

Combine the pieces into one script and record what it finds.

Create check_report.py. You may copy from your earlier scripts. The report uses one event per line, beginning with OK or WARN.

Your task

  1. Ask for the practice URL, download it and decode it as UTF-8.
  2. Loop over text.splitlines(). Print only the lines that start with WARN.
  3. Count those lines and print the total.
  4. Save the total to summary.txt, then open that file and check it.

Two useful lines are shown below. startswith(...) checks the start of a string. In an f-string, Python substitutes the value inside braces into the text. The f goes immediately before the opening quote.

Python · pieces to use in your script
if line.startswith("WARN"):
    print(line)

summary = f"Warning lines: {warnings}\n"

This is a fragment, not a complete script: your loop must supply line, and your counter must supply warnings. Remember to import Path if you use it to save the summary.

Hint 1: arrange the steps

Reuse the download and decode steps from Part 6. Set warnings = 0 before a loop beginning for line in text.splitlines():. Put the if inside the loop. Increase the counter only inside the if.

Hint 2: save the count

After the loop, build summary using the f-string above. Print it, then save it with Path("summary.txt").write_text(summary, encoding="utf-8"). The save line goes outside the loop.

Check your result
Expected findings
WARN test account unused
WARN sample file missing
Warning lines: 2

Your script may also print the HTTP status and byte count. The file summary.txt should contain Warning lines: 2.

To check your counting logic, temporarily replace the downloaded text with text = "OK all clear\n" before the loop. The total should become zero. Restore the download afterwards. This test does not need another network request if you temporarily remove the download block too.

Keep a short record

In your notes, record the input URL, the script you ran and the two warning lines. Explain why you decoded the response before looking for "WARN". This habit will help you make your later coursework investigations reproducible.

Optional · outside the two-hour route

If you have time

Choose one exercise. These introduce ideas you can return to later.

A. Package the repeated work in a function

A function lets you name a piece of work and reuse it. def defines it, the parameter text receives its input, and return sends a result back. Create functions.py:

Python · functions.py
def count_warnings(text):
    warnings = 0
    for line in text.splitlines():
        if line.startswith("WARN"):
            warnings = warnings + 1
    return warnings

print(count_warnings("OK one\nWARN two\n"))
print(count_warnings("OK one\n"))

Check that the outputs are 1 and 0. Add a third test with two warning lines. Then use the function in your report checker.

B. Recognise a Base64 representation

Base64 represents bytes using printable characters. It is reversible without a secret key and provides no confidentiality. Create encoding_practice.py:

Python · encoding_practice.py
import base64

raw = b"A small practice message"
encoded = base64.b64encode(raw)
print(encoded)
print(base64.b64decode(encoded).decode("utf-8"))

Change the message and repeat the round trip. Explain which variables contain bytes and why the last line also calls decode("utf-8"). Base64 decoding recovers the bytes; UTF-8 decoding interprets them as text.

C. Handle a failed request

An exception reports a problem. try runs some code, and a matching except handles a particular kind of exception. Create fetch_with_errors.py:

Python · fetch_with_errors.py
from urllib.request import urlopen
from urllib.error import HTTPError, URLError

url = input("Paste the practice URL: ").strip()
try:
    with urlopen(url, timeout=10) as response:
        raw = response.read()
except HTTPError as error:
    print("HTTP error:", error.code)
except URLError as error:
    print("Could not reach the URL:", error.reason)
except TimeoutError:
    print("The request timed out")
else:
    print(raw.decode("utf-8"))

Try the valid practice URL and the missing filename from Part 6. HTTPError must come before URLError because it is a more specific kind of that error. Here, else runs only if the try block succeeds. This example handles common request failures; it still assumes the response is UTF-8 text.

When something goes wrong

Read the last line of the error first, then find the line number in your own script. Change one thing and run it again.

Message or symptomWhat to check
SyntaxErrorLook for a missing quote, parenthesis or colon. The mistake can be just before the reported position.
IndentationErrorUse four spaces per block level. Do not mix tabs and spaces.
NameErrorCheck spelling and capitalisation, and that the variable was assigned before this line ran.
TypeErrorCheck whether you have text, bytes or a number. print(type(value)) shows a variable’s type; replace value with its actual name.
FileNotFoundErrorCheck the extracted folder, relative path and current working folder. See Part 5.
UnicodeDecodeErrorThe bytes do not match the encoding you chose. For the binary sample, inspect bytes or hex instead.
HTTPError: 404Check the full practice URL and filename. This is the expected result of Part 6’s missing-file test.
URLError or timeoutCheck the URL and network connection. If using the local server, check it is still running and the port matches. Try the local fallback in Part 6 if needed.
Certificate verification failedAsk a demonstrator to check the Python installation or use the local fallback. Keep HTTPS certificate verification enabled.
Script seems to do nothingCheck for an input prompt waiting in the Shell or terminal. Save your file, and check that you ran the right one.
