Part 3: 20 minutes

Classify and count responses

Create responses.py. A list stores values in order. A for loop processes one item at a time. Run this example, then read the explanation before changing it.

Python: responses.py
statuses = [200, 403, 404, 200, 500, 302, 403, 200, 429, 500, 200, 404]

for status in statuses:
    if status >= 400:
        print("Failed request:", status)

The indented code runs once for each status. if selects a block when its condition is true. Use four spaces per indentation level. A colon starts each block.

A condition can use == (equal), != (not equal), <, >, <= or >=. elif tests another condition if the earlier one was false, and else handles anything left. For example:

Python: example of a choice inside the loop
if 200 <= status < 300:
    print("Success")
elif 300 <= status < 400:
    print("Redirection")
else:
    print("Another category")

Create a separate counter for each category, initially zero, before the loop. Increase the matching counter with an assignment such as client_errors = client_errors + 1. Put the final print statements outside the loop. Check len(statuses) before calculating a percentage.

Part 4: 20 minutes

Interpret a binary record

Create records.py. A byte is eight bits and has a value from 0 to 255. Python distinguishes text (str) from sequences of bytes (bytes). Run this example first:

Python: records.py
text = "caf\u00e9"
raw = text.encode("utf-8")
print("Characters:", len(text))
print("Bytes:", len(raw))
print("Hex:", raw.hex())
print(raw.decode("utf-8"))

The escape \u00e9 represents an e with an acute accent. This string has four characters but needs five UTF-8 bytes. encode converts text to bytes; decode interprets bytes as text. hex() displays each byte as two hexadecimal digits.

Byte positions start at zero. raw[0] gives the first byte as an integer. raw[0:3] gives a slice containing positions 0, 1 and 2. The end position is excluded.

Exercise: validate the record before decoding it

A small binary format stores a signature, a length and a text payload:

Byte positionsMeaning
0-3The four bytes b"LAB1"
4-5Payload length as an unsigned, two-byte, big-endian integer
6 onwardsThe UTF-8 payload

Add the following record to records.py:

Python: record to inspect
record = bytes.fromhex("4c4142310005636166c3a9")
  1. Extract and print the signature, declared length and payload bytes.
  2. Check that the signature is correct and the actual payload length matches the declared length.
  3. Decode and print the payload only when both checks pass. Otherwise print an explanation of what is wrong.
  4. Repeat with 4c4142310005636166c3. Explain why your program should reject this record before attempting UTF-8 decoding.

bytes.fromhex converts hex text to bytes. To read a two-byte big-endian length, use int.from_bytes(record[4:6], "big"). Big-endian means the more significant byte comes first.

Hint: select the right slices

The signature is record[:4] and the payload is record[6:]. Compare the signature with b"LAB1", not the string "LAB1". Use len(payload) for the observed size. Keep the decode operation inside the successful validation branch.

Expected results

The complete record has 11 bytes: a 4-byte signature, a 2-byte length and a 5-byte payload. The length field is 00 05. Its payload is the same accented word as the first example. The shortened record declares 5 payload bytes but contains 4; the last character is incomplete.

Additional task: construct a record

Encode a different message. Build a record using b"LAB1" + len(payload).to_bytes(2, "big") + payload. The length must count bytes, not characters. Feed the result into your validator and check that the original text is recovered.

Do not remove undecodable bytes to make a damaged record appear valid. A length check and a character-encoding check answer different questions.

Python: fetch_colleges.py
from pathlib import Path
from urllib.request import urlopen

url = "https://en.wikipedia.org/wiki/Colleges_of_Durham_University"

with urlopen(url, timeout=15) as response:

urlopen makes an HTTP GET request. response.read() reads the response body as bytes. The script saves those bytes in colleges.html and prints the first 200 bytes.

Part 7: 25 minutes

Return the list of colleges

Use Beautiful Soup to select the college names from the saved HTML. The package is installed as beautifulsoup4 and imported as bs4; see Requirements.

Create list_colleges.py. This starting example selects the table and prints the college in its first data row.

Python: list_colleges.py
from pathlib import Path
from bs4 import BeautifulSoup

raw = Path("colleges.html").read_bytes()
page = BeautifulSoup(raw, "html.parser")

heading = page.find(id="List_of_colleges")
if heading is None:
    raise ValueError("Cannot find the List of colleges section")

table = heading.find_next("table")
if table is None:
    raise ValueError("Cannot find the college table")

rows = table.find_all("tr")
first_row = rows[1]
cells = first_row.find_all(["th", "td"], recursive=False)
print(cells[1].get_text(" ", strip=True))

BeautifulSoup parses the saved bytes into HTML elements. It detects their character encoding. find(id="List_of_colleges") finds the section marker, and find_next("table") selects the table after it. The two raise ValueError lines stop the script with an explanation if the expected structure is missing.

find_all("tr") returns the rows. Row zero contains the column headings, so row one is the first data row. find_all(["th", "td"], recursive=False) selects that row's immediate cells. The first cell contains the shield and the second contains the college name. get_text(" ", strip=True) extracts text, separating nested pieces with spaces and removing surrounding whitespace.

Worked example 1: 10 minutes

Encode and decode a message

Encoding changes a representation. UTF-8 represents text as bytes; hexadecimal and Base64 represent bytes using printable characters. Neither hexadecimal nor Base64 needs a secret key to reverse it.

Create encoding_data.py:

Python: encoding_data.py
import base64

text = "Meet at 10:30"
raw = text.encode("utf-8")

hex_text = raw.hex()
base64_bytes = base64.b64encode(raw)

print("Hex:", hex_text)
print("Base64:", base64_bytes.decode("ascii"))

from_hex = bytes.fromhex(hex_text)
from_base64 = base64.b64decode(base64_bytes, validate=True)

print(from_hex.decode("utf-8"))
print(from_base64.decode("utf-8"))
print("Same bytes:", from_base64 == raw)

base64.b64encode(...) returns bytes containing ASCII characters. Decoding those as ASCII makes the printed representation easier to read. base64.b64decode(...) recovers the original bytes; validate=True makes the decoder reject characters outside the Base64 alphabet. UTF-8 decoding then recovers the message.

Exercise

Change the message to "caf\u00e9 at 10:30" and repeat the round trip. Does the final comparison still print True? Can you recover the message using only its Base64 representation?

Then change the Base64 text to include an exclamation mark and run the strict decoder. Record the exception. Explain why rejecting malformed Base64 does not establish that a successfully decoded message is authentic.

Expected result

The original message produces hex 4d6565742061742031303a3330 and Base64 TWVldCBhdCAxMDozMA==. Both decoding routes print Meet at 10:30. The comparison prints True, meaning the bytes match. Anyone with the encoded value can decode it; encoding provides no confidentiality.

Reference: Python base64 documentation.

Worked example 2: 15-20 minutes: cryptography package

Encrypt and decrypt data

Encryption protects a message using a key. We will use Fernet, an authenticated encryption tool from the cryptography package. It checks the encrypted message before returning decrypted data. The same secret key is used to encrypt and decrypt: this is symmetric encryption.

Create encrypt_data.py:

Python: encrypt_data.py
from cryptography.fernet import Fernet

key = Fernet.generate_key()
cipher = Fernet(key)

message = "A private practice message"
plaintext = message.encode("utf-8")
token = cipher.encrypt(plaintext)

print("Encrypted:", token.decode("ascii"))
recovered = cipher.decrypt(token)
print("Decrypted:", recovered.decode("utf-8"))

Fernet.generate_key() creates a random key. Fernet(key) prepares an object whose methods use that key. encrypt takes plaintext bytes and returns an encrypted token; decrypt returns the original bytes. You do not need to write a class to use these methods.

The token is represented in Base64, but Base64 decoding alone does not decrypt it. Its message contents are protected by the key; the token's creation timestamp is visible.

Exercise

  1. Run the script twice. Check that the encrypted output changes but the decrypted message stays the same.
  2. After creating token, add second_token = cipher.encrypt(plaintext) and print(token == second_token). Even with the same key and message, fresh randomness makes the tokens different.
  3. Add the wrong-key experiment below at the end of your script.
  4. Test tampering as well as the wrong key. Use the hint below to change one byte inside a token without breaking its Base64 representation. Decryption must reject it.
Hint: alter a token while keeping valid Base64

Append this to the script after creating token. bytearray is a mutable sequence of bytes, and ^ 1 changes one bit. Catch InvalidToken when attempting to decrypt the result, as in the wrong-key test.

Python: prepare a tampered token
import base64

token_bytes = bytearray(base64.urlsafe_b64decode(token))
token_bytes[-1] = token_bytes[-1] ^ 1
tampered = base64.urlsafe_b64encode(token_bytes)
Python: add to encrypt_data.py
from cryptography.fernet import InvalidToken

other_key = Fernet.generate_key()
other_cipher = Fernet(other_key)

try:
    other_cipher.decrypt(token)
except InvalidToken:
    print("This key cannot decrypt the message")

try attempts the decryption. except InvalidToken handles the failure and prints an explanation.

Expected result

The decrypted text is A private practice message. The wrong-key experiment prints This key cannot decrypt the message. With the original key, decryption succeeds.

Encrypt a file and write the recovered data

Add this to encrypt_data.py. It reuses cipher and its key from above. The same read/encrypt/decrypt/write steps work for any small file that fits in memory.

Python: add to encrypt_data.py
from pathlib import Path

original = Path("data/practice-report.txt").read_bytes()
encrypted = cipher.encrypt(original)
Path("report.encrypted").write_bytes(encrypted)

stored_token = Path("report.encrypted").read_bytes()
restored = cipher.decrypt(stored_token)
Path("report-recovered.txt").write_bytes(restored)
print("Recovered exactly:", restored == original)

Open report-recovered.txt; its contents should match the supplied report, and the script should print True. To try an image instead, read data/sample-image.png, save the token to image.encrypted, read that same token file back, and write the decrypted bytes to image-recovered.png. Open the recovered PNG in an image viewer.

About the key This example uses a fresh key on every run and keeps it only in memory. It demonstrates a round trip in one run; it will not recover an old token after the script has ended. Decrypting later requires the original key, kept privately and separately from the encrypted file. Do not upload keys to GitHub or print them in your notes.

Reference: Fernet documentation.

Worked example 3: 15-20 minutes

Read and write images

Use the supplied sample-image.png. It is a 96 x 64 pixel PNG with red, green and blue blocks.

Read and write the file bytes

Create image_bytes.py. This example needs no extra package.

Python: image_bytes.py
from pathlib import Path

raw = Path("data/sample-image.png").read_bytes()
print("First eight bytes:", raw[:8])
Path("sample-image-copy.png").write_bytes(raw)

The first eight bytes are b'\x89PNG\r\n\x1a\n': the PNG file signature. Open sample-image-copy.png in an image viewer. It is an exact byte copy. PNG file bytes include headers and compressed image data; they are not a simple sequence of RGB pixel values. Do not decode a PNG as UTF-8.

Read the pixels with Pillow

Create image_pixels.py. The package is installed as Pillow but imported as PIL.

Python: image_pixels.py
from PIL import Image

with Image.open("data/sample-image.png") as source:
    print("Format:", source.format)
    print("Size:", source.size)
    print("Mode:", source.mode)
    image = source.convert("RGB")

print("Top-left pixel:", image.getpixel((0, 0)))
print("Middle pixel:", image.getpixel((40, 20)))

Image.open identifies the image format. convert("RGB") loads a version with red, green and blue channels. The with block closes the source file afterwards; the converted image remains available.

A pixel position is a pair (x, y): x counts from the left, y from the top, starting at zero. An RGB colour is a triple (red, green, blue), with each value from 0 to 255. These comma-separated values in parentheses are tuples, which group values together.

with Image.open("edited-image.png") as saved:
    print("Saved pixel:", saved.getpixel((0, 0)))

new_image = Image.new("RGB", (96, 64), (87, 43, 104))
new_image.save("created-image.png")

putpixel changes the top-left pixel to white. save writes a PNG because the filename ends in .png. Image.new creates a new image filled with the chosen colour. Open both output files in an image viewer; zoom in to see the changed pixel.

Encode a whole image as Base64, then write it back

Create image_base64.py. The image stays as bytes throughout; only its Base64 representation is handled as text.

Python: image_base64.py
import base64
from pathlib import Path

original = Path("data/sample-image.png").read_bytes()
encoded = base64.b64encode(original)
Path("image-base64.txt").write_text(encoded.decode("ascii"), encoding="ascii")

stored_text = Path("image-base64.txt").read_text(encoding="ascii")
restored = base64.b64decode(stored_text, validate=True)
Path("image-from-base64.png").write_bytes(restored)
print("Same file bytes:", restored == original)

Open image-from-base64.png. It should display the original three blocks, and the comparison should print True. This example does not need Pillow.

C. Handle a failed request

An exception reports a problem. This version handles common request errors. Read it before running it; there is no need to send another request if you already saved the article.

Python: fetch_with_errors.py
from pathlib import Path
from urllib.request import urlopen
from urllib.error import HTTPError, URLError

url = "https://en.wikipedia.org/wiki/Colleges_of_Durham_University"
try:
    with urlopen(url, timeout=15) as response:
        raw = response.read()
except HTTPError as error:
    print("HTTP error:", error.code)
except URLError as error:
    print("Connection failed:", error.reason)
except TimeoutError:
    print("The request timed out")
else:
    Path("colleges.html").write_bytes(raw)
    print("Saved bytes:", len(raw))

HTTPError is a specific kind of URLError, so its handler comes first. The else block runs only if the request succeeds. On failure, an existing colleges.html is left unchanged; do not mistake it for a new download.
